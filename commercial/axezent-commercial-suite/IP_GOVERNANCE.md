# AXEZENT Intellectual-Property Governance

## Corporate rule

**Protect before disclosing. Verify before claiming. Separate public proof from private discovery machinery.**

## Background IP

All pre-existing AXEZENT business systems, research systems, inventions, software, algorithms, private discovery methods, architecture, patent drafts, claim concepts, designs, datasets, know-how, and trade-secret material are treated as background IP unless a signed instrument states otherwise.

The public six-cycle mathematics paper is a public research disclosure. Publication of a theorem does not place unrelated private AXEZENT systems or unpublished implementations into the public domain.

## Patent truth labels

Use only evidence-backed status labels:

- CONCEPT / RESEARCH
- DRAFT_READY_NOT_FILED
- PROVISIONAL_FILED — only with a filing receipt/application number
- NONPROVISIONAL_FILED — only with a filing receipt/application number
- PATENT_PENDING — only when legally accurate for the filed application
- ISSUED_PATENT — only with an issued patent number

Do not describe an invention as patented, patent-pending, priority-secured, or protected by a filed application without documentary evidence.

## Public-release gate

Before publishing implementation details for a potentially patentable invention:

1. identify the invention and inventorship record;
2. preserve dated source/engineering records;
3. run a prior-art/patentability review appropriate to the investment level;
4. decide trade-secret vs patent strategy;
5. obtain filing advice where protection matters;
6. only then approve public disclosure.

## Trade-secret boundary

Keep private unless specifically cleared:

- Unified Formula / branch-scoring internals;
- recursive A-Z search strategy;
- automatic coefficient-discovery logic;
- automatic positivity-certificate discovery;
- cross-problem theorem-transfer rules;
- counterexample-selection logic;
- private theorem-discovery backend;
- unpublished patent claims and enabling implementation details;
- customer confidential information.

## Repository rule

Public GitHub repositories may contain verification artifacts, public papers, public clients, API contracts, product documentation, and non-sensitive examples. They must not contain private signing keys, billing secrets, unpublished enabling patent detail, confidential customer data, or private discovery-engine internals.

## Release evidence

Every important release should preserve, where applicable:

- author/inventor attribution;
- date and version;
- source commit/hash;
- verification status;
- claim scope;
- known limitations;
- third-party dependency/license record;
- publication/disclosure date.
